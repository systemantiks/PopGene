## Windows build difference

The pinned graphics dependency normally generates release shader bytecode with
the Windows SDK's `fxc.exe` on a Windows build host. Its original debug fallback
loads HLSL from the build host's absolute source path, which is unsuitable for a
downloaded cross-build.

The isolated Windows source vendors the exact dependency and embeds its unchanged
shader sources and shared include. It compiles them in memory with `D3DCompile`
using the original entry points/profiles and the release pipeline's optimization
level. Only that renderer package enables debug assertions to select the upstream
runtime shader path; this also retains its graphics-debug probing/diagnostics and
debug panic handling. Application crates retain the optimized release profile.
The patch, original dependency identity and exact configuration accompany the
Windows source. This is a candidate configuration, not a claim of ordinary native
Windows release validation; the main checkout's build configuration is unchanged.

## Remaining acceptance

Target-specific notice inventories retain unresolved provenance gaps and fail
strict distribution review. Additional platform notices are preserved as explicit
packaging overlays, including a declaration-only `hexf-parse` gap on Linux.
macOS lacks a Developer ID distribution certificate and notarization profile.
Windows runtime/MSVC and broader release acceptance remain outstanding. No stable
update feed was generated for these candidates.

See [consolidated build notes](0.0.1-consolidated.md) for feature coverage and
scientific/format limitations. The new optimized Linux smoke test and Windows
compile do not replace the earlier full test matrix or establish every GUI path.
