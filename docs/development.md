# Development and validation

The current working tree is unreleased. Tests and reference checkers establish their recorded cases, not native usability, complete format fidelity or release acceptance. Use the [acceptance checklist](implementation-checklist.md) for the remaining gates.

## Rust checks

Use Rust 1.99.1 and the platform's C compiler/SDK. Download dependencies before offline checks. `scripts/cargo-local` selects an optional ignored `.tools/` toolchain; ordinary installations can use Cargo directly.

```sh
cargo fetch --locked
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all --check
```

During shared editing, format only owned files; run the workspace formatting check after integration. Thermodynamics includes compiled C. The CI definition lists Linux system libraries; a configured job is not evidence of a passed run.

## Synthetic fixtures

Read [fixture provenance](../validation/fixtures/README.md) before changing test data. The native generator has a read-only mode:

```sh
python3 validation/generate_native_fixtures.py --check
```

`generate_fixtures.py`, `generate_native_fixtures.py` without `--check`, and `prepare_trace_parameters.py` overwrite fixtures. Do not run them over user-modified data, including the current local `validation/fixtures/synthetic-pcr.dna` change. `scripts/make-demo-project.py` creates a disposable ignored project folder.

## Scientific and format checks

Create the developer-only environment with pinned dependencies:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r validation/requirements.lock
```

These checkers take no arguments and compare production Rust output with reference expectations:

```sh
.venv/bin/python validation/check_translation.py
.venv/bin/python validation/check_alignment.py
.venv/bin/python validation/check_traces.py
.venv/bin/python validation/check_primer3.py
.venv/bin/python validation/check_restriction.py
.venv/bin/python validation/check_protein_properties.py
.venv/bin/python validation/check_protein_models.py
.venv/bin/python validation/check_cloning.py
.venv/bin/python validation/check_annotation_lineage.py
```

Run from the repository root with cached Cargo dependencies: these builds use `--locked --offline`. These checkers use `validation/rust_probe.py`, which mirrors cargo-local's toolchain selection, discovers actual Cargo artifacts and respects `CARGO_TARGET_DIR`. No ignored absolute compiler path or macOS-only target directory is required.

Primer design settings are checked in at `validation/fixtures/primer3-design-settings.json`, with a hash of the synthetic template. No ignored result file is needed. Primer3 wrapper comparisons share source lineage; a separate default Tm comparison uses Biopython. This tests integration without claiming independent proof of the physical theory.

`check_translation_fixtures.py` checks fixture expectations only, explicitly without executing production Rust. Standard export verification uses a separate reader:

```sh
scripts/cargo-local run --locked --offline -p popgene-formats --example interoperable_exports -- /tmp/popgene-standard-exports
.venv/bin/python validation/check_standard_exports.py /tmp/popgene-standard-exports
```

Reports live under ignored `validation/results/`. Keep command, source revision/hash, tool versions and result scope with acceptance evidence. Rerun relevant checks when their production behavior changes.

## Independent ZTR encoder checks

These scripts compile public Staden io_lib C encoders into temporary libraries, generate synthetic vectors and exercise production decoding. They rewrite their synthetic trace fixture subdirectories. They require `cc`; the reference harnesses have been exercised on macOS, not accepted on every platform.

Supply the `compression.c`, `deflate_interlaced.c` and `deflate_interlaced.h` revisions identified by the scripts' source URLs and SHA-256 constants. These are public validation inputs, not proprietary application source. Hash checks reject mismatched revisions before compilation.

```sh
.venv/bin/python validation/check_ztr_extended.py --reference-source /tmp/popgene-iolib-compression.c
.venv/bin/python validation/check_ztr_float.py
.venv/bin/python validation/check_ztr_huffman.py --reference-source /tmp/popgene-deflate-interlaced.c --reference-header /tmp/popgene-deflate-interlaced.h
```

The extended and Huffman checkers expose `--help`. The floating checker takes no arguments and reads `/tmp/popgene-iolib-compression.c`. It pins binary32 arithmetic, disables fused contraction and documents its correction to the old encoder's short-block returned length; it does not prove all historical floating encoders compatible. Reference shared libraries are temporary and must not be packaged.

## Figure checks

Generate outputs from production tests, then run the Poppler-based checker (`pdfinfo` and `pdftotext` must be on PATH):

```sh
POPGENE_FIGURE_QA_DIR="$PWD/validation/results/figure-qa" scripts/cargo-local test --locked --offline -p popgene-desktop figure
.venv/bin/python validation/check_figures.py
```

This checks PDF/PNG dimensions, PNG density/CRC and each paginated sequence row exactly once in text extraction. Also view representative figures: check text contrast, label clipping, translations, selected circular ranges, physical overhangs, long headers and page breaks.

## Native acceptance

Use disposable synthetic copies. Exercise all document views and analysis dialogs, narrow windows, linked selections, split resizing, independent sidebar scrolling and display/filter settings. Test edit/undo/redo, save/reopen and conversion warnings with nullable qualities, alternate calls, full-duplex annotations, circular cloning/alignment, references, attachments and history. Unavailable source data must stay explicit. Check canceled/failed exports and preservation of citation drafts during attachment export.

Distinguish the automated killed-child SQLite regression from native recovery: edit documents and creator drafts, terminate/relaunch a disposable app instance, compare original bytes/recovered state, and alter a source externally before saving. Identify the executable/build and environment in each acceptance record. Headless startup or an older build does not sign off the final interactive app.
