# File formats and data preservation

This describes the development tree as of 26 October 2026, not a released or fully accepted build. Native application checks and the [release acceptance gates](implementation-checklist.md) remain separate from codec tests.

Save updates the selected document's supported source format. Save As selects a new format and path; Export writes a copy without changing the open document. Writers validate the encoded representation before replacing a destination. Format-specific warnings identify known losses and refused conversions.

| Format | Implemented behavior | Material limits |
| --- | --- | --- |
| Native `.dna`, `.rna`, `.prot` | DNA/RNA/protein, topology, strandedness, features, primers, Notes, references, per-strand colors, physical duplex ends and overhang annotations. Original embedded files can be extracted and embedded ZTR traces opened separately. Stored alignment/enzyme/RNA metadata and history parameters can be inspected; supported snapshots restore as new documents. | Original record inspection does not apply stored settings or create an editable RNA structure diagram. Unsupported history operations remain unavailable. See native preservation below. |
| GenBank / GenPept | Multi-record input; single-document output. Structured references, qualifiers and typed exact, fuzzy, compound, between-base and remote locations. Conventional annotation color/direction/segment/cleavage notes are interpreted and written. | Unresolved locations do not acquire invented sequence. Unbound oligos have no INSDC location and cannot be converted without removal. Display extensions depend on reader support; whitespace and unsupported reference attributes may be normalized or represented as remarks. |
| EMBL | Multi-record nucleotide input; single-document output, typed locations, qualifiers and structured references. | Protein output is unavailable. Unbound oligos are refused. Additional source headers and display conventions are not universally portable across formats. |
| FASTA | Multi-record input; single-document output. Use `.faa`/`.pep` for protein and `.frna` for RNA when saving. | Sequence and record name only; annotations, references, qualities, topology and physical ends are omitted. Molecule intent otherwise depends on filename/content. |
| ABIF `.ab1` / `.abi` | Calls, peaks, analyzed A/C/G/T signals, edited/basecaller families and bounded instrument-record inspection. Editing, trimming and call-family selection are available; imported ABIF files can be rewritten with updated calls. | Writing requires an ABIF source. The edited family is replaced; original signals and other instrument records remain. Display crop and per-call manual flags do not reopen. Missing confidence remains unknown. |
| SCF `.scf` | Version 2/3 signals, peaks and confidence; portable version 3 output. Original SCF comments/private bytes are retained where applicable. | Export requires known confidence. Crop, alternate families and application annotations are omitted; instrument records from other formats are not portable to SCF. |
| ZTR `.ztr` | Signals, calls, peaks, confidence and comments; bounded standard transformation decoding, shared Huffman tables and checksum validation. Portable trace output. | LOG2 amplitudes are quantized approximations. Obsolete floating Chebyshev decoding follows a documented binary32/reference-byte convention and warns about historical precision differences. Edited output omits unmodeled chunks, uncalled confidence channels and crop. |
| FASTQ `.fastq` / `.fq` | Wrapped, multi-record Phred+33 input; single-record sequence/quality output. | Every exported base needs a known quality; unknown is never silently Phred zero. No Phred+64 guessing. Signal, peaks, annotations and alternate calls are omitted. RNA U is written as T and reopens as DNA. |
| Legacy `.popgene` | Read-only migration import. | Save As to a supported public format; no new private sequence container is written. |

Multi-record imports are atomic: malformed records do not leave a partially opened batch. Each tab retains its original record slice and must be saved separately; saving a tab does not rewrite the complete multi-record input. The parser supports up to 1,024 records, while the desktop admits at most 64 tabs and 256 MiB of source attachments. Files are bounded to 128 MiB and sequences to ten million symbols; codecs also enforce expansion/allocation limits.

## Native preservation

An unchanged same-format save preserves source bytes. Native edited saves retain supported independent metadata and embedded files, preserve unchanged Feature/Primer XML records selectively, and archive sequence-dependent original records in recoverable history when the molecule changes. Changed records are rebuilt from modeled data; this does not promise every source field remains current state.

Exact local ranges and joins with a uniform strand can be written as native segments, including fully retained annotations from generated products. Nested exact syntax normalizes to ordered segments while preserving the extracted sequence, strand, names and colors. Fuzzy endpoints, remote references, mixed strands and unsupported operators remain refused rather than silently becoming exact spans; GenBank and EMBL retain their supported location syntax. Focused tests and independent extraction/translation checks cover this export change. A Linux Golden Gate/native save/close/reopen check retained exact reverse locations, citations and strand colors; remaining native interoperability checks are pending.

Exact full-length primer matches can be saved as native primers. Complex/unverified bindings and additional qualifiers may instead be saved as `primer_bind` annotations, with a warning. Rebuilt primers do not claim to retain source hybridization filters, chemistry or measured melting temperatures. Native cleavage-arrow positions are imported, remapped and written using verified interbase coordinates, including reverse features. Native line-style conversion remains refused until its encoding is verified; unchanged packets can be retained and conventional GenBank/EMBL notes remain available.

Uncolored primer annotations use a stable PopGene purple display fallback (`#b985d0`), independent of their position in the annotation list. Native Save/reopen therefore preserves their displayed color even when packet grouping changes their order. This is an application display style: the recorded color remains absent and no color attribute is invented. The Primers table shows a swatch only for a recorded recognized color. Controlled reference-app editing verified the named orange value and a Black dialog default for an uncolored primer; its purple annotation labels are a separate display style. Arbitrary native primer-color values are not assumed to be supported.

Unrecognized native segment types produce an aggregate import warning and retain their original values as source provenance. Their ranges use a provisional display fallback; unknown appearance and biological semantics are not interpreted. Unchanged records can keep their original XML during unrelated edits. Native saving refuses to rebuild an affected annotation when that XML cannot be retained, preventing silent normalization to a standard segment. Explicit annotation deletion remains possible. If deletion followed by a new annotation reuses the same internal ID, the conservative guard may also refuse that replacement; save and reopen after deletion before adding the new annotation.

History restoration supports complete snapshots and verified REMOVE/INSERT residue undo actions. Unknown actions are inspectable but not executed. Inherited attachment pools are labeled shared source provenance; they do not establish when a file was attached. Current methylation flags are not inferred from absent history data.

Original-record inspection decodes embedded trace containers (block 16), stored alignment XML and BGZF/BAM (17/27), custom enzyme/visibility XML (14/28), and XZ-compressed RNA JSON (34). BAM records require an unambiguous stored read-ID association; malformed or unsupported records show a decoding explanation. Coordinates, RNA indices and probabilities remain explicitly original data, not reconstructed current document state. Display and decompression limits are disclosed, with full bytes retained for recovery.

Embedded traces open as separate unsaved ZTR documents with their original calls, peaks, confidence and signal. Container orientation is shown as provenance rather than silently transforming the calls. An unchanged ZTR Save As preserves the embedded bytes; edits follow ordinary ZTR loss warnings. Stored alignments are inspected as records, independently of newly calculated alignments. Supported explicit named enzyme panels can be loaded from the original source into a draft, reviewed and applied manually. Unknown member names are retained and must be corrected before applying. Active-panel and visibility settings are not inferred; unsupported panel types remain inspectable in original records. Interactive native comparison of these new views is still pending.

Circular DNA with zero terminal stickiness may carry inactive terminal-modification fields. These are retained as original metadata with a warning and do not create physical ends on the closed molecule. Nonzero stickiness on circular DNA is rejected.

Recorded whole-template Dam/Dcm/EcoKI flags initialize the applicable digestion assumptions; they are not measurements of site occupancy. Sequence edits make the current flags unknown and retain a historical note. Physical digestion and reversal preserve recorded template flags. CpG starts unset in the simulation, and EcoKI sensitivity and partial/site-specific methylation are not modeled.

## Coordinate and calculation semantics

Displayed ranges are 1-based inclusive. Ordinary sequence views and standard sequence exports use the stored top-strand axis. **Analyze → Full duplex strands & annotations…** shows actual physical strands, protruding residues, full-extent annotations and strand-specific quality. An absent opposite residue is not drawn as a fabricated complement. A documented [physical-fragment comment extension](physical-fragments.md) now preserves supported linear double-stranded fragments in GenBank/EMBL, including opposite residues, end chemistry, full-extent annotations and nullable qualities. Standards-only readers still see the actual top strand; removing or invalidating the extension loses its supplemental data. Other unsupported conversions save the top strand with explicit loss warnings.

CDS translations use current sequence, location, phase and genetic code. There are 27 active NCBI codes, supported exact translation exceptions, partial endpoints, six-frame tracks, ORFs and selected-CDS flanks, including circular-origin handling. Unresolved remote, mixed-strand, ordered or alternative CDS locations produce an explanation instead of a guessed translation. Imported cached translations remain provenance.

Primer thermodynamics uses explicit reaction parameters for unmodified, unambiguous, perfect-match DNA oligos; it is not a mismatch/degenerate-site model or a PCR annealing-temperature recommendation. Protein secondary structure is a labeled Chou–Fasman estimate. Digestion uses explicit methylation assumptions and curated conditions; unknown cuts and unestablished activities are not invented. Alignment and cloning retain their stated algorithm and exact-binding limits.

## Recovery and figures

Annotation reconstruction has a new development [readable ancestry convention](annotation-lineage.md). Its typed coordinate and annotation records can use ordinary GenBank/EMBL/native comments when the target preserves their prerequisites. It does not replace missing physical ends or extend unsupported native location grammar. The separate GenBank/EMBL physical-fragment extension is activated before ancestry validation. Actual codec Save/reopen/rejoin tests pass, while integrated desktop/platform/GUI acceptance remains in progress; preserving a session is a separate capability from saving a lossless fragment file.

Transactional recovery stores unsaved documents, creator drafts, display settings and checksummed original bytes in a separate local SQLite database. External file changes detach recovered documents from old save paths. Recovery restores the saved baseline and recovered state as one undoable change, not the previous complete undo stack. It is application recovery, not an independent backup of every file.

Map/sequence SVG, PDF and PNG figures use current layers and enzyme filters. Sequence figures retain original coordinates and optional selected regions; PDF pages break between complete rows. SVG text is outlined for portability and PNG records physical-pixel density. Crowded-label and row-limit omissions are disclosed. Figures do not preserve editable sequence data.

Source terminology remains in imported metadata, fixture provenance and licenses. Native containers implement the publicly documented SnapGene format; this identifies the format, not affiliation or complete compatibility. No proprietary application binaries or source are distributed with PopGene.

Native primer-packet settings are preserved separately from individual primer records. When the molecule and emitted original primer records/order are unchanged, the complete original packets are retained byte-for-byte. Changes to a verified simple packet retain its supported hybridization settings and next-ID lower bound, even when the last primer is deleted. Rebuilding an unknown, repeated or interspersed packet envelope is refused with an actionable message. This does not infer additional native hybridization behavior.
